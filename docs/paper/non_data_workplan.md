# SiteXRD-Bench Non-Data Workplan

This plan covers the work required for a KDD benchmark paper beyond collecting
and generating the raw dataset. A task is complete only when it produces a
versioned artifact that can be released or cited by the manuscript.

## 1. Claim and Scope Control

Deliverables:

- frozen title, TL;DR, abstract, and four contribution statements;
- explicit exclusion of catalyst and downstream property-prediction claims;
- claim-evidence matrix linking every abstract sentence to an artifact, table,
  experiment, or citation;
- terminology table for structure truth, derived labels, task eligibility,
  simulated observations, and experimental observations.

Acceptance:

- no claim depends on planned but unavailable data;
- "first" or "to our knowledge" claims are backed by the literature matrix;
- performance relevance appears only as scientific motivation.

## 2. Formal Task Specification

Deliverables:

- mathematical definitions for the two primary tasks, HEA-SRO and
  Gamma-Decomp, plus non-leaderboard identifiability diagnostics;
- declared input-information settings and target masks;
- permutation-invariant component matching specification;
- task eligibility manifests and JSON schemas;
- policy for ambiguous or physically non-identifiable cases.

Acceptance:

- an independent implementation can compute every target from released truth;
- no target or review metadata leaks into model inputs;
- every sample either enters a task or has an explicit exclusion reason.

## 3. Metrics and Evaluation Toolkit

Deliverables:

- reference metric implementation with unit tests;
- SRO masks and macro/micro aggregation rules;
- component matching cost and tie-breaking rules;
- phase-fraction, lattice-parameter, misfit, and disorder metrics;
- whole-pattern and forward-consistency metrics reported separately;
- calibration and prediction-interval metrics;
- bootstrap confidence intervals and random-seed aggregation.

Acceptance:

- metrics are invariant to allowed element/component permutations;
- synthetic perfect predictions score exactly at the optimum;
- deliberately wrong latent predictions cannot pass through good spectral fit;
- metric outputs are reproducible from a submitted prediction file.

## 4. Split and Leakage Design

Deliverables:

- frozen ID, composition OOD, occupancy OOD, instrument OOD, and
  simulation-to-experiment manifests;
- group keys for structures, near duplicates, mixtures, and augmentations;
- nearest-neighbor leakage audit in structure and spectrum spaces;
- split statistics and distribution plots.

Acceptance:

- no canonical structure or augmentation family crosses a split;
- same-composition occupancy controls remain grouped according to task policy;
- OOD test groups are absent from training under the declared shift variable;
- all split decisions are deterministic from versioned configuration.

## 5. Identifiability Protocol

Deliverables:

- spectral and latent distance definitions;
- same-composition pair and neighborhood construction;
- identifiable, weakly identifiable, and non-identifiable challenge slices;
- oracle analysis measuring target variation within a spectral tolerance;
- uncertainty-evaluation protocol for these slices.

Acceptance:

- thresholds are chosen on training/validation data, not tuned on test results;
- examples are manually inspected for physical and numerical artifacts;
- the paper distinguishes empirical ambiguity from a proof of uniqueness.

## 6. Baseline Suite

Deliverables:

- metadata-only control;
- peak-feature baseline;
- 1D residual CNN;
- sequence baseline such as a Transformer or state-space model;
- physics-constrained latent-to-XRD model;
- constrained pseudo-Voigt gamma/gamma-prime fitting baseline;
- common training, checkpoint, and prediction interfaces.

Acceptance:

- all models consume the same released splits and input settings;
- at least three seeds are reported for learned baselines;
- compute budgets and hyperparameter search spaces are documented;
- every baseline writes the standard prediction format consumed by metrics.

## 7. Main Experiments and Ablations

Deliverables:

- ID and OOD leaderboard for all tasks;
- metadata shortcut comparison;
- weak-peak and superlattice-peak ablation;
- composition-information ablation;
- component-supervision ablation;
- perturbation-randomization ablation;
- random-split versus controlled-split comparison;
- simulation-to-experiment evaluation at supported label levels.

Acceptance:

- every table is generated by a checked-in script from frozen predictions;
- negative or null results are retained;
- the paper reports uncertainty over seeds or bootstrap samples;
- experimental claims do not exceed available ground-truth levels.

## 8. Literature and KDD Positioning

Deliverables:

- structured related-work matrix;
- primary-source bibliography with no fabricated citations;
- explicit KDD relevance statement covering structured prediction, inverse
  problems, data-centric evaluation, OOD, and uncertainty;
- comparison against existing XRD datasets and scientific benchmarks.

Acceptance:

- Table 1 is reproducible from the literature matrix;
- each novelty claim has a documented search scope and date;
- materials-specific background is concise enough for a data-mining audience.

## 9. Reproducibility and Release

Deliverables:

- public archival dataset release with DOI, checksums, and licenses;
- public source repository and immutable release tag;
- dataset card, benchmark card, schema documentation, and examples;
- one-command small smoke benchmark;
- full generation and evaluation environment locks;
- artifact-badging checklist and maintenance policy.

Acceptance:

- reviewers can access data without a personal request;
- a clean environment can reproduce the smoke result;
- all paper tables can be regenerated from public or reviewer-accessible files;
- source and generated artifacts have clear redistribution rights.

## 10. Paper Production

Deliverables:

- ACM `sigconf,review` LaTeX manuscript;
- eight-page self-contained submission body;
- appendix containing schemas, algorithms, extended results, and audits;
- five main figures and three main tables;
- generative-AI disclosure text for the submission form;
- OpenReview profile and qualified-reviewer readiness check.

Acceptance:

- the main eight pages contain the problem, benchmark, tasks, baselines, and
  primary results without requiring the appendix;
- all figures remain readable in two-column print;
- abstract numbers match the frozen release exactly;
- no unresolved result placeholders remain at submission time.

## Recommended Execution Order

1. Freeze task definitions and eligibility.
2. Implement and test metrics and prediction schemas.
3. Freeze controlled splits and leakage audits.
4. Complete identifiability-set construction.
5. Implement baselines and run pilot experiments.
6. Freeze the complete benchmark release.
7. Run all baselines, OOD evaluations, and ablations.
8. Complete literature matrix and rewrite related work.
9. Generate tables and figures from frozen outputs.
10. Convert the working draft to the ACM LaTeX submission.
